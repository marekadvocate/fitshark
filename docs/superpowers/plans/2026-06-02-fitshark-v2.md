# Fitshark v2 — Cross-Catalog Marketplace Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild Fitshark as a cross-catalog marketplace on Duvo: central Questions + Orders files, a Master Catalog Index for searching all 11 supplier catalogs, agents (owned by Marek) that infer intent and reply with branded HTML emails carrying a unique per-customer buy link.

**Architecture:** Data lives in Google Sheets (11 catalog-only files + Master Index + Questions + Orders). A `fitment-producer` polls Questions and enqueues normalized cases; a `fitment-consumer` searches the Master Index, decides via skills, drafts a localized HTML reply, pauses at a HITL gate, sends via Gmail, and logs to Orders. Local Python scripts (gcloud Drive/Sheets API) build/load the data; Duvo MCP creates the orchestration objects under Marek's API key.

**Tech Stack:** Duvo MCP (`mcp__duvo__*`), Google Sheets/Drive API via `.venv` + gcloud ADC token (account `marekpodhorsky1993`), Python 3, Git (repo `marekadvocate/fitshark`).

**Key IDs:** team `78c96305-46bc-466c-83f7-d7761daea24a`; queue `fitment_intent` `ca600d25-f6e2-451e-a02d-a9f6e3f83b13`; Marek Sheets conn `d20c49a9-9141-46d4-8bb8-3afe3378aa84`; Marek Gmail conn `aacd14a9-8c24-491d-918f-99203557e18d`; Sheets integration type `033fca4f-4349-4a06-b35a-3d1c7120b237`; Gmail integration type `860e50d2-9941-4ec5-9c33-29c77146a3ba`; skills: fitment-decision `b7cf089a-893a-4615-9dd6-339789ff3930`, fitshark-product-link `e2ef1fd7-d4c6-4a8d-9ce5-1deeb274b37d`, fitshark-reply-writer `3b3f3a5d-f482-4c6e-b3fa-ddeec525242c`, seller-voice `17b629d7-ce99-44ee-82b3-7fbc63a2d2fa`.
